# orca-dash

Orca 에이전트 상태를 터미널에서 한눈에 보는 TUI 대시보드입니다. `orca worktree ps --json` 결과를 주기적으로 읽어 표로 보여 주고, 선택한 에이전트에게 프롬프트를 보내거나 로컬 claude·codex로 프롬프트 초안을 만들 수 있습니다. 실행 방법과 키는 `orca_dash.py` 상단 설명을 참고하세요.

## 옵션

조회 간격, 조회할 소스(로컬·`--env`·`--host`·`--ssh`), AI 초안 공급자·모델·제한 시간은 대시보드 안에서 `o` 키로 보고 고칩니다. 저장하면 `~/.config/orca-dash/config.json`에 기록되고 재시작 없이 바로 적용됩니다. 같은 항목을 명령줄 인자로 주면 그 값이 파일보다 우선하며, 설정 화면에 어떤 항목이 명령줄로 고정되어 있는지 표시됩니다. 설정 파일 위치는 `--config`로 바꿀 수 있습니다.

옵션 화면의 「자동 전송」 탭에서는 사람 없이 초안을 보내도 되는 조건을 정합니다. 기본은 꺼짐이고, `--auto-send on|off` 로 이번 실행만 켜거나 끌 수 있습니다. 조건의 뜻은 아래 「자동 전송 정책」에 있습니다.

macOS에서는 메인 화면이 앞에 있을 때 키보드 입력 소스를 영문(ABC)으로 자동 전환하고, 프롬프트·옵션 창을 열거나 다른 앱으로 가거나 종료하면 원래 입력 소스로 되돌립니다. 터미널 앱은 물리 키코드 대신 IME가 조합한 글자만 받기 때문에 한글 상태에서는 `q` 같은 단축키가 자모 조합 중 상태에 머물러 듣지 않는데, 이 전환으로 한글 상태에서도 단축키가 바로 동작합니다. 메인 화면에서 Caps Lock이나 ⌃Space로 한글로 바꿔도 1초 주기 감시가 다시 영문으로 돌려 놓습니다(메인 화면에는 글자를 입력할 곳이 없으므로). 옵션 화면의 「영문 자동 전환」으로 끌 수 있고, 꺼진 경우에도 같은 자리의 두벌식 자모(ㅔ ㅐ ㄱ ㄹ ㄷ ㅂ)가 단축키로 동작합니다. 한글 입력기로 되돌리는 쪽은 macOS 버그로 API 호출만으로는 적용되지 않아, `scripts/build-im.sh`로 빌드하는 작은 보조 실행 파일 `bin/orca-dash-im`(macism과 같은 방식·인터페이스, Xcode Command Line Tools 필요)을 씁니다. 앱 빌드 스크립트가 함께 빌드하며, 대신 `brew tap laishulu/homebrew && brew install macism`으로 설치한 macism도 자동으로 인식합니다. 창 닫기 버튼이나 Cmd+Q, kill로 끝나도 종료 신호를 받아 되돌리고, 그마저 못 받고 죽은 경우에는 다음 실행이 남겨 둔 기록을 이어받아 종료 때 되돌립니다.

## AI 초안과 작성 에이전트

프롬프트 창(`p`)에서 `Ctrl+G`를 누르면 로컬 `claude -p` 또는 `codex exec`가 선택한 에이전트의 상황을 보고 프롬프트 초안을 써 줍니다. 메모를 적고 누르면 그 의도로 초안을 만들고, 초안이 들어 있는 상태에서 다시 누르면 다듬습니다. 같은 창의 `Ctrl+T`는 초안이 아니라 작업의 달성·계속·막힘을 판정합니다(아래 「진행 판정」). 어떤 관점으로 쓸지는 창 위의 「작성 에이전트」 목록에서 체크합니다(Tab으로 이동, Space로 토글). 여러 개를 체크하면 각 에이전트가 같은 상황과 메모로 독립적으로 초안을 쓰고, 체크한 순서대로 `[목표 지향]`, `[문제 발견]` 같은 머리말을 붙여 하나의 프롬프트로 묶습니다. 에이전트 하나가 끝날 때마다 그 부분이 입력창에 들어오고 Esc로 중단하면 끝난 부분까지 남습니다. 초안이 들어 있는 상태에서 다시 Ctrl+G를 누르면 머리말로 나눠 각 에이전트가 자기 부분만 다듬습니다. 마지막에 쓴 조합과 순서가 다음의 기본값이 되고, 옵션 화면의 「작성 에이전트」(id를 순서대로 공백 구분)나 `--ai-agent`(반복 가능)로도 지정합니다. 기본 제공 에이전트는 두 가지입니다.

| id | 이름 | 보는 것 | 쓰는 것 |
|---|---|---|---|
| `goal` | 목표 지향 | 원래 지시 · 마지막 응답 · 프로젝트 목표 문서(`GOAL.md`, `docs/GOAL.md`, `.orca-dash/goal.md` 중 첫 번째, 없으면 README 앞부분). **사용자 메모는 받지 않음** | 이번 작업이 목표의 어느 항목에 기여하는지 짚고, 목표에 가장 가까운 다음 한 단계를 지시 |
| `review` | 문제 발견 | 원래 지시 · 마지막 응답 · `git diff`(커밋 전 변경과 main 대비 변경) · 최근 커밋 · **저장소 파일 직접 읽기**(Read·Grep·Glob) | 변경분의 버그·누락된 예외 처리·테스트 공백을 파일 경로와 함께 짚고 고치라고 지시 |
| `final` | 최종 결정 | 원래 지시 · 마지막 응답 · 사용자 메모 · **다른 에이전트들이 쓴 초안** · 저장소 파일 직접 읽기(Read·Grep·Glob) | 초안들을 평가해 충돌을 가르고 좋은 부분만 합쳐, 머리말 없는 프롬프트 하나로 정함 |

최종 결정 에이전트는 다른 에이전트들과 함께 체크하면 체크 순서와 상관없이 맨 마지막에 한 번 실행됩니다. 작성 에이전트들의 초안이 머리말과 함께 `[에이전트 초안]` 절로 들어가고, 그 출력이 머리말 없는 최종 프롬프트로 입력창의 묶음을 대체합니다. 실행 순서 줄에는 「목표 지향 → 문제 발견 ⇒ 최종 결정」처럼 표시됩니다. 최종 결정이 들어 있는 상태에서 다시 Ctrl+G 를 누르면 작성 에이전트들은 다시 돌지 않고 최종 결정 에이전트만 그 프롬프트를 다듬습니다. 결정 전에 Esc 로 중단했거나 한 에이전트가 실패해 입력창에 머리말 묶음이 남아 있으면(직접 고쳐도 됩니다), 다음 Ctrl+G 는 작성 에이전트를 다시 돌리지 않고 그 묶음을 최종 결정 에이전트에게 넘겨 결정만 합니다. 최종 결정만 단독으로 체크하면 받을 초안이 없어 상황과 메모로 직접 씁니다. 사용자 정의 에이전트도 frontmatter 에 `final: on` 을 적으면 같은 자리에서 동작하며, 최종 결정 에이전트를 여럿 체크하면 마지막으로 체크한 하나만 쓰입니다.

목표 지향 에이전트는 입력창의 메모를 받지 않습니다. 메모가 있으면 목표 대신 메모를 좇으면서 억지로 목표 항목에 끼워 맞추는 경향이 있어, 목표 문서와 에이전트 상황만 보고 다음 한 단계를 정하게 합니다. 메모를 받지 않는 에이전트는 목록과 실행 순서에 「메모 안 받음」으로 표시됩니다. 목표 문서와 변경분은 에이전트가 로컬 호스트에 있을 때만 읽고, 원격이면 생략했다고 표시합니다. 옵션의 「에이전트 상황 전달」을 끄면 상태 한 줄만 보내고 지시·응답·저장소 내용은 모두 보내지 않습니다.

각 에이전트에는 「생각의 흐름」이 있습니다. 초안을 쓰기 전에 순서대로 거치는 생각 단계 목록입니다. 초안 요청 본문에는 에이전트 명세가 아래 JSON으로 함께 들어가고, 시스템 프롬프트가 `character`는 역할 id(지시문은 시스템 프롬프트의 「역할」에 있음), `think_steps`는 번호 순서대로 거치는 생각 단계이며 생각 과정은 출력하지 말고 최종 프롬프트만 출력하라고 지시합니다.

```json
{
  "agent": {
    "character": "review",
    "think_steps": {
      "1": "변경분에서 바뀐 파일과 함수를 파악한다",
      "2": "각 변경의 입력·경계 조건·실패 경로를 따라가며 문제를 찾는다"
    }
  }
}
```
 옵션(`o`)의 「에이전트」 탭에서 에이전트를 고른 뒤 각 단계를 고치고, 「+ 단계 추가」로 단계를 더하거나 각 줄의 「-」로 빼며, 「기본값으로」를 누르면 그 에이전트의 기본 단계로 돌아갑니다. 단계를 모두 지우면 역할 지시문만으로 씁니다. 기본값과 다른 에이전트만 설정 파일의 `agent_steps`에 저장됩니다.

### 백그라운드 제안

옵션(`o`) 일반 탭의 「백그라운드 제안」을 켜면(설정 파일의 `auto_draft`, 기본 꺼짐) 프롬프트 창을 열고 Ctrl+G 를 눌러 기다릴 필요 없이, 조회할 때마다 사람의 다음 지시가 필요한 행의 프롬프트를 뒤에서 미리 만들어 둡니다. 대상은 상태가 막힘·입력 대기·권한 대기(`blocked`, `waiting`, `permission`, `waiting_input`, `waiting_permission`)이고 에이전트 터미널이 있는 행이며, AI 공급자가 꺼져 있거나 `--file` 소스이면 만들지 않습니다. 옵션의 「작성 에이전트」 조합과 생각의 흐름을 그대로 쓰고 사용자 메모는 비워 둡니다. 저장소 내용(목표 문서·변경분)은 프롬프트 창과 같은 기준으로 에이전트가 로컬 호스트에 있을 때만 읽습니다. 여러 행이 대상이면 막힘, 대기(최근에 갱신된 것 먼저) 순서로 큐에 넣어 한 번에 하나씩만 만듭니다.

제안의 상태는 표의 상태 열 끝에 붙습니다.

| 표시 | 뜻 |
|---|---|
| `제안 …` | 작성 중 |
| `제안 ✓` | 준비됨. 행을 고르면 아래 상세 창에 본문이 보이고, `p` 로 열면 입력창에 들어와 있어 Enter 만 누르면 전송 |
| `제안 ✗` | 실패. 상세 창과 프롬프트 창 상단에 사유가 보임 |

준비된 제안이 있는 행의 프롬프트 창을 열면 제안이 입력창에 들어가고 마지막 초안으로 등록되어, Ctrl+G 는 새로 쓰지 않고 (메모 없이) 다듬습니다. 내용을 지우고 메모를 적은 뒤 Ctrl+G 를 누르면 평소처럼 새 초안을 씁니다. 프롬프트 창에서 Ctrl+G 로 직접 만든 초안도 그 행의 제안으로 저장되어, 창을 닫았다 다시 열어도 남아 있습니다.

제안은 메모리에만 두며 대시보드를 끄면 사라집니다. 행의 갱신 시각(`updatedAt`)이 바뀌면 에이전트가 다시 움직인 것이므로 그 제안을 버리고, 여전히 대상 상태이면 새로 만듭니다. 프롬프트를 보낸 행은 조회가 아직 옛 상태를 돌려주더라도 갱신될 때까지 다시 만들지 않습니다. 실패한 제안은 다음 조회 때 다시 시도하되 같은 갱신 시각에 대해 2번까지만 시도하고, 행이 갱신되면 횟수가 초기화됩니다. 제안은 자동으로 전송되지 않습니다.

에이전트를 추가하려면 `~/.config/orca-dash/agents/<id>.md`를 만듭니다. 파일 이름이 id가 되고, 내장 에이전트와 같은 id면 그것을 덮어쓰므로 기본 지시문을 고치는 데도 쓸 수 있습니다. 프롬프트 창을 열 때마다 다시 읽으므로 재시작은 필요 없고, 형식이 잘못된 파일은 건너뛰고 창 상단에 이유를 보여 줍니다.

프로젝트마다 다른 에이전트가 필요하면 그 저장소 안에 `.orca-dash/agents/<id>.md`를 같은 형식으로 둡니다. 에이전트가 로컬 호스트에 있을 때 프롬프트 창을 열면 사용자 디렉터리 다음에 읽혀 같은 id의 정의를 덮어씁니다(내장 < 사용자 디렉터리 < 저장소). 형식이 잘못된 파일은 같은 방식으로 건너뛰어 앞 단계의 정의가 남고 이유가 창 상단에 보입니다. 옵션 화면의 「에이전트」 탭은 특정 저장소를 보지 않으므로 내장과 사용자 디렉터리 정의만 보여 주고, 그 탭에서 고친 생각의 흐름(`agent_steps`)은 같은 id의 저장소 정의에도 적용됩니다. 저장소 정의는 그 저장소의 내용이 초안의 역할 지시문을 바꾸는 것이므로, 믿을 수 없는 저장소라면 `.orca-dash/agents/`에 무엇이 있는지 먼저 확인하세요. 줄 수 있는 도구는 어디서 정의하든 읽기 전용 세 가지뿐입니다.

```
---
name: 테스트 작성
description: 변경분에 맞는 테스트를 쓰게 한다
context: diff, log          # instruction · last_message · goal · diff · log 중에서, 생략하면 instruction, last_message
step: 변경분에서 테스트가 없는 분기를 찾는다
step: 각 분기에 맞는 테스트를 설계한다
memo: on                    # off 면 입력창의 사용자 메모를 요청에 넣지 않음 (생략하면 on)
final: off                  # on 이면 최종 결정 에이전트로 동작: 다른 초안들을 받아 하나로 정함 (생략하면 off)
tools: Read, Grep, Glob     # 저장소를 직접 읽는 도구. Read · Grep · Glob 만 가능 (생략하면 도구 없음)
model: sonnet               # 이 에이전트만 쓸 모델 (생략하면 옵션의 모델)
timeout: 120                # 이 에이전트만 쓸 제한 시간(초) (생략하면 옵션의 제한 시간)
---
역할: 변경된 코드의 테스트를 설계하는 사람.
- 변경분에서 테스트가 없는 분기와 경계 조건을 찾아 어떤 테스트를 어디에 추가할지 지시한다.
- 기존 테스트 파일과 같은 방식·위치를 따르게 한다.
```

`tools`를 적은 에이전트는 잘린 변경분만 보고 쓰지 않고 저장소 파일을 직접 열어 확인한 뒤 씁니다. 내장 `review`와 `final`은 기본으로 세 도구를 모두 갖고, `goal`은 도구 없이 씁니다. claude 로 호출할 때 `--tools Read,Grep,Glob --permission-mode dontAsk --strict-mcp-config`를 붙이고 작업 디렉터리를 그 저장소로 둡니다. 내장 도구는 적은 것만 남고, 저장소 안 읽기는 권한 질문 없이 되며, 저장소 밖 읽기처럼 권한이 필요한 것은 묻지 않고 거절되고, 사용자 MCP 서버의 도구는 끼어들지 않습니다. `Edit`·`Write`·`Bash` 같은 쓰기·실행 도구를 적으면 그 파일은 오류로 건너뜁니다. 에이전트가 원격 호스트에 있거나 옵션의 「에이전트 상황 전달」이 꺼져 있으면 도구를 주지 않습니다. codex 는 원래 읽기 전용 샌드박스(`-s read-only`)에서 돌며 저장소를 읽을 수 있어 `tools`와 무관하게 그대로 호출합니다. `model`과 `timeout`은 공급자와 상관없이 그 에이전트에 한해 옵션의 모델·제한 시간보다 우선합니다. 도구를 쓰면 호출이 여러 턴이 되어 느려지므로(이 저장소 기준 claude haiku 로 도구 없이 8초 안팎, 도구를 쓰면 20초 안팎) 큰 저장소에서 제한 시간에 걸리면 `timeout`을 늘리세요. 옵션의 「에이전트」 탭 설명에 각 에이전트의 도구·모델·제한 시간이 표시됩니다.

값이 정해진 줄(`context`·`memo`·`final`·`tools`·`model`·`timeout`)에는 위 예시처럼 값 뒤에 `# 설명`을 달 수 있습니다. `name`·`description`·`step` 줄은 줄 전체가 값이라 주석을 달 수 없습니다. `step`은 생각의 흐름 기본값으로, 여러 줄 반복해 적으며 생략할 수 있습니다.

## 자동 전송 정책

orca-dash 의 최종 목표는 사람이 Enter 까지 넘기는 자율 루프입니다(`GOAL.md`). 그 전제로 "어떤 조건에서 스스로 보내도 되는가"를 설정과 함수 하나로 정해 둡니다. `auto_send_allowed(settings, row, history)` 가 행 하나에 대해 `(허용 여부, 한국어 사유)` 를 돌려주고, 자동 전송은 이 판정이 허용일 때만 일어납니다. 이 함수는 판정만 하며 전송이나 기록은 하지 않습니다. `history` 는 그 행의 최근 전송 기록으로, 각 항목에 `at`(epoch 초)·`text`·`auto`(자동 전송 여부)가 있고 순서는 가리지 않습니다.

| 설정 (`config.json` 키) | 기본 | 뜻 |
|---|---|---|
| `auto_send` | `false` | 전체 켬/끔. 꺼져 있으면 "자동 전송 꺼짐" |
| `auto_send_repos` | `{}` | 저장소 이름별 켬/끔. 적힌 저장소는 전체 설정보다 우선하므로, 전체를 끈 채 `repo:on` 으로 한 저장소만 켤 수 있음. 화면에서는 `repo:on repo2:off` 한 줄 |
| `auto_send_states` | `["waiting_input"]` | 보내도 되는 상태. `waiting` 과 `waiting_input` 은 같은 입력 대기로 봄 |
| `auto_send_waits` | `["질문"]` | 보내도 되는 대기 사유. Orca 의 대기 사유를 `권한`·`중단`·`질문`·`없음` 으로 분류해 비교하고, 분류에 안 맞는 사유는 글 그대로 비교. 사유가 비어 있는 입력 대기는 `질문` |
| `auto_send_max_streak` | `3` | 사람 개입 없이 연속으로 보내는 상한. 최근 기록부터 `auto` 가 참인 항목이 이어지는 수를 세고, 사람이 직접 한 번 보내면 0으로 돌아감 |
| `auto_send_cooldown` | `120` | 같은 행의 마지막 전송(자동·수동 모두) 뒤 다시 보내기까지의 최소 간격(초). 0 이면 검사 안 함 |
| `auto_send_require_final` | `true` | 작성 에이전트(`ai_agents`)에 최종 결정 에이전트가 있어야 함. 초안이 머리말 묶음이 아니라 프롬프트 하나로 정해졌을 때만 보내기 위함 |

검사는 위에서부터 켬/끔 → 에이전트 터미널 → 상태 → 대기 사유 → 최종 결정 에이전트 → 연속 상한 → 최소 간격 순서이고, 처음 걸린 사유 하나를 돌려줍니다. 사유는 "자동 전송 꺼짐", "저장소 X 는 꺼짐", "에이전트 터미널 없음", "상태 working 은 허용 안 됨", "대기 사유 권한 은 허용 안 됨", "작성 에이전트에 최종 결정 에이전트 없음", "연속 3회 상한", "마지막 전송 후 85초 (120초 미만)" 같은 한 줄입니다. 권한 대기(`permission`)와 막힘(`blocked`) 상태, `권한` 대기 사유는 설정에 적어도 저장할 때 오류로 막고, 설정 파일을 손으로 고쳐 넣어도 판정에서 항상 거부합니다. 권한 요청은 사람이 답한다는 원칙입니다.

최종 결정 에이전트 여부는 기본적으로 내장 에이전트의 `final` 표시와 id `final` 로 판단합니다. frontmatter 에 `final: on` 을 적은 사용자 정의 에이전트까지 인정하려면 `auto_send_allowed(..., agents=load_agents(...)[0])` 처럼 읽어 둔 에이전트 목록을 넘깁니다.

## 진행 판정

자동 전송이 영원히 돌거나 같은 지시를 되풀이하지 않도록, 작업이 끝났는지·더 시킬 일이 남았는지·사람이 봐야 하는지를 가르는 부품입니다. 자동 전송 루프 자체는 여기에 없고, 루프가 이 판정을 불러 멈출지 정합니다. 지금은 프롬프트 창(`p`)에서 `Ctrl+T`로 사람이 직접 요청할 수 있습니다. 입력창의 내용은 건드리지 않고 창의 상태 줄에 「진행 판정: 막힘 — 사유」로 보여 주며, 닫은 뒤에도 표의 상태 칸에 「· 판정 달성」「· 판정 막힘」으로, 아래 상세에 사유와 함께, 상태 줄에 「판정: 달성 1 · 막힘 2」로 남습니다. 판정 뒤에 에이전트가 더 움직였으면 「(이전)」을 붙여 흐리게 표시합니다. 판정 중에 Esc를 누르면 판정만 중단됩니다.

판정은 내장 에이전트 `verdict`(「진행 판정」)가 합니다. 프롬프트 초안을 쓰는 에이전트가 아니므로 프롬프트 창의 「작성 에이전트」 목록과 옵션의 「작성 에이전트」 값에는 나오지 않고, 옵션의 「에이전트」 탭에서 생각의 흐름만 고칠 수 있습니다. `~/.config/orca-dash/agents/verdict.md`나 저장소의 `.orca-dash/agents/verdict.md`(뒤쪽이 우선)를 두면 역할 지시문과 컨텍스트를 바꿀 수 있고, 어떻게 정의해도 사용자 메모는 받지 않습니다.

| 보는 것 (요청 본문의 절 순서) | 내는 것 |
|---|---|
| 에이전트 상황 · 원래 지시 · 마지막 응답 · 프로젝트 목표 문서 · `git diff` · 최근 커밋 · **최근 전송 기록**(최근 8건, 한 줄에 300자까지, 자동 전송은 「(자동)」 표시) | `{"verdict": "done" \| "continue" \| "stuck", "reason": "<한국어 한 문장>"}` 하나 |

`done`은 「달성」(원래 지시와 목표의 해당 항목이 끝남), `continue`는 「계속」(다음 지시나 답을 보내면 더 나아감), `stuck`은 「막힘」(같은 오류·질문의 반복, 진전 없는 전송, 사람만 정할 수 있는 결정)입니다. 시스템 프롬프트는 초안용과 달리 이 JSON만 출력하게 하고, 코드 펜스나 앞뒤 설명이 붙어 와도 첫 번째로 해석되는 객체를 씁니다. AI가 꺼져 있거나 실패·빈 응답·깨진 JSON이면 루프를 막지 않도록 `continue`에 「판정 실패: …」 사유로 돌려주고 화면에는 「판정 실패」로 표시합니다. 옵션의 「에이전트 상황 전달」을 끄면 다른 에이전트와 마찬가지로 상태 한 줄만 보내고 전송 기록도 보내지 않습니다.

AI를 부르기 전에 전송 기록만으로 헛도는지 먼저 봅니다. 걸리면 AI 호출 없이 「막힘」입니다.

- **같은 지시 반복**: 최근 자동 전송 3회의 본문이 서로 `difflib` ratio 0.8 이상으로 닮았을 때.
- **변경 없이 반복**: 최근 자동 전송 3회 시점의 저장소 상태 값이 모두 같을 때. 값은 HEAD 커밋에 커밋 전 변경의 해시를 붙인 것이라, 커밋하지 않고 고치기만 해도 달라집니다. 전송 기록에 이 값(`head`)이 없으면 이 규칙은 건너뜁니다.

사람이 보낸 전송은 세지 않습니다. 코드에서 쓰는 이름은 다음과 같습니다.

| 이름 | 하는 일 |
|---|---|
| `judge_progress(cfg, row, repo_dir, history, *, agent=None, cwd=None) -> Verdict` | 위 순서로 판정. 예외를 내지 않음. `history`는 그 행의 전송 기록 `[{"at": epoch, "text": str, "auto": bool}, …]` |
| `Verdict(verdict, reason)` | `.label`(달성·계속·막힘·판정 실패) · `.failed`(판정을 못 했는지) |
| `is_stalled(history, heads=None) -> (bool, 사유)` | 위 두 규칙. `heads`는 최근 자동 전송 시점들의 저장소 상태 값(오래된 것부터), 없으면 각 기록의 `"head"` |
| `repo_head(repo_dir) -> str` | 전송할 때 기록해 둘 저장소 상태 값 |
| `notify_user(title, text)` | macOS 알림 센터(`osascript`)로 사람을 부름. 다른 OS이거나 실패하면 조용히 넘어감 |
| `OrcaDash.set_verdict(row, verdict, alert=False)` | 판정을 표에 기록. `alert`이면 달성·막힘일 때 `notify_user`까지 |

## 자동 전송

설정 파일의 `auto_send` 를 `true` 로 두면, 새로고침이 끝날 때마다 대시보드가 행을 훑어 **정책이 허용하고 준비된 제안이 있는 행 하나**에 그 제안을 사람 없이 Orca 터미널로 보냅니다. 사람이 Enter 로 보낼 때와 같은 전송 경로(`orca terminal send`)를 씁니다. 보내는 조건은 모두 만족해야 합니다.

조건을 모두 만족한 행도 보내기 직전에 「진행 판정」을 한 번 거칩니다. 먼저 전송 기록만으로 같은 지시 반복·변경 없는 반복을 보고, 아니면 판정 에이전트가 달성·계속·막힘을 가립니다. 달성이나 막힘이면 보내지 않고 macOS 알림으로 사람을 부르며, 전송 기록에 `result: "보류: 진행 판정 막힘: …"` 으로 남깁니다. 판정에 실패하면(AI 꺼짐, 깨진 응답) 정책대로 보내되 `policy` 에 그 사유를 덧붙입니다. 자동 전송 기록에는 저장소 상태 값(`head`)이 함께 남아 다음 판정의 「변경 없이 반복」 감지에 쓰입니다.

- 일시 정지 상태가 아니다. 메인 화면에서 `a`(한글 자판 `ㅁ`)를 누르면 일시 정지와 재개가 바뀌고, 상태 줄에 「자동 전송 ON · 오늘 n회」, 「자동 전송 일시 정지 · 오늘 n회」, 꺼져 있으면 「자동 전송 OFF」가 보입니다. 일시 정지는 저장되지 않아 다시 띄우면 풀려 있습니다.
- 그 행에 유효한 제안이 있다. 제안은 상태가 `ready` 이고 내용이 있으며 행의 지금 턴(`updated_at`)에 대해 만든 것이어야 합니다. **제안이 없으면 보내지 않습니다.** 자동 전송이 직접 작성 에이전트를 돌리지는 않습니다.
- 정책(`auto_send_allowed`)이 허용한다. 저장소별 켬/끔(`auto_send_repos`, 없으면 `auto_send`), 상태(`auto_send_states`, 기본 `waiting_input`), 대기 사유(`auto_send_waits`, 기본 `질문`, 비우면 모든 사유), 사람 개입 없는 연속 자동 전송 한도(`auto_send_max_streak`, 기본 3회 — 사람이 한 번 보내면 다시 셉니다), 같은 행의 재전송 대기 시간(`auto_send_cooldown`, 기본 120초)을 봅니다.
- `auto_send_require_final`(기본 켬)이면 최종 결정 에이전트를 거친 제안만 보냅니다.
- 에이전트 터미널이 있는 행이고 파일 소스가 아니며, 그 행의 프롬프트 창을 사람이 열어 두지 않았다.

한 번의 새로고침에는 가장 오래 기다린 행 하나에만 보내고, 앞선 자동 전송이 끝나지 않았으면 건너뜁니다. 성공이든 실패든 같은 턴(`updated_at`)에는 다시 시도하지 않으며, 이 판단은 기록 파일로도 하므로 다시 띄워도 같은 턴에 두 번 보내지 않습니다. 실패한 전송은 연속 횟수와 대기 시간에 세지 않습니다. 표의 「자동 전송」 열에는 그 행에 성공한 자동 전송 횟수와 마지막 시각이, 아래 상세 창에는 마지막 판단(「보류 — 연속 자동 전송 3회 …」 등)이 보입니다.

사람이 보낸 것과 자동으로 보낸 것은 모두 설정 파일과 같은 디렉터리의 `send-log.jsonl`(기본 `~/.config/orca-dash/send-log.jsonl`)에 한 줄에 JSON 하나씩 덧붙여 기록합니다. 기록을 쓰지 못하면 연속 횟수와 대기 시간을 셀 수 없으므로 자동 전송을 일시 정지하고 알립니다.

| 키 | 내용 |
|---|---|
| `at` | 전송 시각 (epoch 초) |
| `row_key` · `repo` · `worktree` · `branch` | 보낸 대상 행 |
| `state` · `wait` | 보낼 때의 에이전트 상태와 대기 사유 |
| `row_updated_at` | 보낼 때 행의 `updated_at` (같은 턴 재전송 방지용) |
| `agent_ids` | 제안을 쓴 작성 에이전트 id 들 (사람이 직접 쓴 경우 빈 목록) |
| `drafts` | 에이전트별 초안 (제안에 있을 때만) |
| `text` | 보낸 프롬프트 |
| `auto` | 자동 전송이면 `true`, 사람이 Enter 로 보냈으면 `false` |
| `policy` | 허용 사유 (예: `상태 … · 대기 사유 질문 · 연속 자동 전송 1/3회`, 사람이면 `사람이 직접 전송`) |
| `result` | `ok` 또는 오류 문자열 |

## 테스트

`tests/run.sh` 가 헤드리스 테스트 열 벌(설정·CLI, 작성 에이전트 등록과 컨텍스트, 생각의 흐름 편집 탭, 최종 결정 경로, 자동 전송 정책, 백그라운드 제안, 진행 판정, 자동 전송, 에이전트 도구, 자동 전송 루프의 진행 판정)을 저장소의 `.venv` 로 차례로 실행합니다. 각 파일은 단독으로도 `python tests/test_agents.py` 처럼 실행할 수 있고, Textual `run_test` 로 실제 화면 흐름까지 확인합니다. 표 표시용 입력은 `tests/fixtures/sample.json` 의 익명화한 `orca worktree ps --json` 출력입니다.

## 커밋 메시지 훅 활성화

이 저장소의 작업 규칙(커밋 규칙, 코드 규칙, 오케스트라가 워크트리 에이전트에게 일을 맡기고 병합하는 절차)은 `AGENTS.md` 에 있습니다. 이 저장소는 `.githooks/commit-msg`로 커밋 메시지 규격(`<type>(<scope>): <한국어 명사구>` 제목과 `- `로 시작하는 본문 bullet 2개 이상)을 검사합니다. 훅은 저장소 안에 들어 있지만 git은 기본적으로 `.git/hooks`만 보므로, 새로 clone한 뒤에는 저장소 루트에서 `git config core.hooksPath .githooks`를 한 번 실행해야 훅이 동작합니다. 규격 전체는 훅 파일 머리의 주석에 있고, 규격에 맞지 않는 메시지는 커밋이 거절되며 이유와 예시가 함께 출력됩니다.

## macOS 앱으로 쓰기 (Orca Dash.app)

터미널 없이 독립된 창과 Dock 아이콘을 가진 앱으로 쓰려면 Alacritty를 껍데기로 쓰는 앱 번들을 만듭니다. Homebrew의 alacritty cask는 공증 미통과로 비활성화되어 있어, 빌드 스크립트가 GitHub 공식 릴리스 dmg를 받아 번들을 복사한 뒤 전용 설정과 실행 스크립트를 넣고 ad-hoc 서명합니다. `gh` CLI 로그인이 필요합니다.

```
scripts/build-app.sh                      # ~/Applications/Orca Dash.app 설치
scripts/build-app.sh --install-dir /Applications
```

앱은 이 저장소의 `.venv/bin/python`으로 `orca_dash.py`를 실행하므로 저장소를 옮기면 다시 빌드해야 합니다. 실행 옵션은 대시보드에서 `o` 키로 바꾸면 설정 파일에 저장되어 앱에도 그대로 적용됩니다. 명령줄 인자로 고정하고 싶은 값만 설치된 앱의 `Contents/Resources/launch.sh` 안 `ARGS` 배열에 적습니다. 창 크기·글꼴은 `app/alacritty.toml`에서 바꾸고 다시 빌드합니다. 개인 Alacritty 설정(`~/.config/alacritty`)과는 무관합니다.
